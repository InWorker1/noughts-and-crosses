# Проект: Игра "Крестики-нолики" с ИИ

## О проекте

Это веб-сервер на Go, который реализует игру "Крестики-нолики" с искусственным интеллектом. Клиент отправляет текущее состояние игрового поля через HTTP-запрос, сервер вычисляет оптимальный ответный ход и возвращает обновлённое поле.

---

## Архитектура проекта

Проект разделён на три слоя по принципу чистой архитектуры:

```
Web (handler) → Domain (бизнес-логика) → Repository (хранение данных)
```

Каждый слой независим и общается через интерфейсы (контракты).

---

## 1. Domain слой — бизнес-логика

### Модели (`internal/domain/models.go`)

**Game** — основная модель игры:
- `ID` — уникальный идентификатор игры (UUID)
- `Field` — игровое поле 3x3

**GameField** — сетка 3x3 (`[][]int`):
- `1` = крестик (X)
- `-1` = нолик (O)
- `0` = пустая клетка

### Контракты/интерфейсы (`internal/domain/service.go`)

**GameService** — интерфейс сервиса игры:
- `GetNextMove(game)` — вычислить следующий ход ИИ
- `ValidateBoard(game)` — проверить корректность доски
- `GameOver(game)` — определить победителя

**GameRepository** — интерфейс репозитория:
- `Save(game)` — сохранить игру
- `Get(id)` — получить игру по ID

### Бизнес-логика (`internal/domain/logic.go`)

Реализация в структуре `gameService`:

**Minimax алгоритм** — ИИ использует классический алгоритм минимакс для поиска лучшего хода. Алгоритм рекурсивно просчитывает все возможные варианты развития игры и выбирает оптимальный ход.

**GetNextMove** — перебирает все свободные клетки, для каждой вычисляет оценку через minimax, выбирает ход с максимальным score. Результат сохраняется в репозиторий.

**ValidateBoard** — проверяет, что клиент не подделал доску:
- Если игра новая (нет в хранилище) — создаёт пустое поле
- Сравнивает новую доску с сохранённой, разрешает только добавление одного нового символа

**GameOver** — проверяет все линии (горизонтали, вертикали, диагонали). Возвращает:
- `1` если выиграли крестики
- `-1` если выиграли нолики
- `0` если никто не выиграл или ничья

## 2. Repository слой — хранение данных

### Хранилище (`internal/repository/sync-map/datasource.go`)

**GameStorage** — обёртка над `sync.Map` для потокобезопасного хранения игр в памяти.

### Маппинг (`internal/repository/sync-map/mapper.go`)

Преобразует domain-модели во внутренний формат хранилища и обратно:

**Storage** — структура для хранения:
- `Key` — UUID игры
- `Value` — GameField

**Функции маппинга:**
- `GameIntoDS` — конвертирует domain.Game в Storage
- `DSIntoGame` — конвертирует Storage обратно в domain.Game

### Реализация репозитория (`internal/repository/sync-map/repo.go`)

**gameRepository** — хранит ссылку на GameStorage

**Методы:**
- `NewGameRepo` — конструктор, возвращает интерфейс `domain.GameRepository`
- `Save(game)` — сохраняет игру в sync.Map через маппинг
- `Get(id)` — загружает игру из sync.Map, возвращает ошибку если не найдена

## 3. Web слой — HTTP обработчики

### Web модели (`internal/web/models.go`)

**JsonRequest** — модель для JSON запросов и ответов:
- `Board` — игровое поле (JSON тег `game`)
- `Winner` — победитель (JSON тег `winner`)

### Маппинг (`internal/web/mapper.go`)

Преобразует web-модели в domain-модели и обратно:

**Функции:**
- `GetJson(game, winner)` — конвертирует domain.Game + победитель в JsonRequest
- `GetDomain(req, id)` — конвертирует JsonRequest + UUID в domain.Game

### HTTP обработчик (`internal/web/handler.go`)

**GameHandler** — хранит ссылку на `domain.GameService`

**Метод Move** — основной handler для endpoint `/game/{uuid}`:
1. Парсит UUID из URL
2. Декодирует JSON из тела запроса
3. Конвертирует в domain-модель
4. Валидирует доску через `ValidateBoard`
5. Если игра новая — возвращает пустое поле
6. Вызывает `GetNextMove` для хода ИИ
7. Проверяет победителя через `GameOver`
8. Возвращает JSON с результатом

---

## 4. Main — точка входа (`cmd/main.go`)

Сборка всех слоёв через Dependency Injection:

1. Создаёт маршрутизатор `http.ServeMux`
2. Создаёт хранилище: `repository.NewGameStorage()`
3. Создаёт репозиторий: `repository.NewGameRepo(storage)`
4. Создаёт сервис: `domain.NewGameService(repo)`
5. Создаёт handler: `web.NewGameHandler(service)`
6. Регистрирует маршрут: `/game/{uuid}` → `gameHandler.Move`
7. Запускает сервер на порту `:8080`

---

## Ключевые особенности

- **Чистая архитектура** — слои не зависят друг от друга напрямую
- **Dependency Injection** — зависимости передаются через конструкторы
- **Потокобезопасность** — используется `sync.Map` для конкурентного доступа
- **Валидация** — проверка подлинности игрового поля
- **ИИ на основе Minimax** — оптимальная стратегия для крестиков-ноликов
